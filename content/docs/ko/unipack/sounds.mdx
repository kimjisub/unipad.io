`sounds` 폴더에는 `keySound` 파일에서 참조하는 사운드 파일을 저장합니다.

## 지원 포맷

| 포맷 | 확장자 | 비고 |
|------|--------|------|
| WAV | `.wav` | 권장 (PCM 16bit) |
| MP3 | `.mp3` | 지원 |
| M4A (AAC) | `.m4a` | 지원 |
| OGG Vorbis | `.ogg` | Android, iOS, 웹에서 지원합니다. |

공통 형식은 OGG Opus(`.ogg`)도 허용합니다. Android와 웹은 재생하며, iOS 지원은 준비 중입니다.
지금 세 앱에서 모두 재생할 팩에는 WAV, MP3, M4A, OGG Vorbis를 쓰세요.

사운드는 확장자가 아니라 파일 내용으로 풉니다. `.wav`로 저장한 MP3도 재생됩니다.

## 예시

```
sounds/
├── kick.wav
├── snare.wav
├── hihat.m4a
├── bass.mp3
└── fx/
    └── sweep.wav
```

<Callout title="참고사항">
- `keySound`에서 파일명으로 참조하므로, 경로와 이름을 대소문자까지 파일과 똑같이 쓰세요.
- 공통 형식은 정확한 경로, 글자 조합 방식을 NFC로 맞춘 경로, NFC로 맞추고 대소문자를 무시한 경로 순서로 찾습니다. 후보가 여럿이면 압축 안의 원래 전체 경로를 UTF-16 코드 단위 순서로 정렬한 첫 파일을 씁니다. 글자 조합만 같고 내용이 다른 항목이 함께 있어도 코드 포인트까지 같은 이름이 우선입니다. 가져올 때 고른 파일을 다른 내용으로 덮어쓰면 안 됩니다. 기기에 저장하는 글자 조합은 달라질 수 있으며, 원래 압축 항목과 그 내용으로 어떤 소리가 선택됐는지 정합니다. 폴더는 소리로 쓰지 않습니다.
- 경로는 `sounds/` 기준입니다. 역슬래시는 `/`로 바꾸고, 앞의 `/`와 `./`는 떼며, 연속된 `/`는 하나로 보고 중간의 `.`은 무시합니다. `..`로 `sounds/` 밖에 나갈 수는 없습니다.
- 이 이름·경로 규칙은 공통 형식의 기준이며, 드문 표기까지 앱별 지원을 맞추고 있습니다. 현재 버전과의 호환을 위해 실제 파일 이름과 일반적인 상대 경로를 그대로 쓰세요.
- 하위 폴더를 사용할 수 있습니다 (예: `fx/sweep.wav`).
- 호환성을 위해 파일명에 **영문, 숫자, 하이픈, 밑줄**만 사용하는 것을 권장합니다.
- 적어도 **30개**의 사운드를 동시에 재생할 수 있습니다.
</Callout>

## 공통 소리 선정 한도

앱 업데이트가 맞추는 정확한 파일 자료 기준입니다. 현재 모든 버전의 재생이나 기기 메모리 여유를
보장하는 뜻은 아닙니다.

샘플레이트를 `r`, 채널 수를 `c`, 채널당 실제 프레임 수를 `n`으로 둡니다. `8000 ≤ r ≤ 384000`,
`1 ≤ c ≤ 8`, `n ≤ 600 × r`이어야 합니다. 환산 프레임은 r이 48000 이상이면 n, 아니면
`올림(n × 48000 ÷ r)`입니다. 비용은 환산 프레임에 `max(c, 2)`를 곱한 값입니다. 소리 하나는
**67,108,864** 이하, 팩 전체는 **134,217,728** 이하이며 경계와 같으면 받습니다. 정수로 계산하고
넘치기 전에 확인합니다. 대략 몇 분이라는 설명으로 이 계산을 대신하지 않습니다.

체인·가로·세로 오름차순, 같은 패드는 키소리 줄 순서로 읽고 팩 범위 밖 줄은 제외합니다.
같은 실제 파일은 처음 나온 자리에서 한 번만 판정합니다. 읽기 실패·개별 한도 초과·남은 합계
초과는 비용을 더하지 않고 다음 작은 파일도 검토합니다. 선정 뒤에만 해독하며 해독 실패나
메모리 부족이 나도 예약한 비용을 뒤 파일에 돌려주지 않습니다. 해독 완료 순서로 선정이 바뀌면
안 됩니다. 같은 파일이 나중에 또 나오면 첫 판정을 유지합니다.

예를 들어 48킬로헤르츠 스테레오 10분짜리 세 소리 다음 44.1킬로헤르츠 스테레오 5초짜리가
있으면 첫째·둘째·넷째를 받습니다. 앞 두 소리 뒤 남은 비용은 19,017,728입니다. 48킬로헤르츠
스테레오 9,508,864프레임은 정확히 들어가며 한 프레임 더는 제외합니다. 44.1킬로헤르츠 경계는
8,736,268프레임입니다.

머리의 시간 표시를 믿지 않고 해독 전에 실제 소리 자료를 확인합니다. 웨이브의 자료 범위,
엠피쓰리 프레임, M4A의 자료와 표, 오그의 페이지가 예약량과 맞아야 합니다. 확장자가 달라도
내용으로 읽습니다. 정상 소리를 잘라 한도에 맞추거나 기존 지원 형식의 읽기를 구현하지 않았다는
이유로 조용히 제외하지 않습니다. 압축 형식의 여분·재생 구간·실제 해독기 출력은 별도 확인이 필요합니다.

규칙상 제외·파일 읽기 실패·선정 뒤 해독 실패·기기 메모리 부족을 구별해 개수를 알리고 자세히
보기에서 파일 이름과 이유를 확인합니다. 일부 실패는 남은 소리로 연주하되 한 안내에 원인별
개수를 함께 보입니다. 참조된 소리가 모두 실패하면 연주 화면 대신 다시 시도와 팩 목록으로
돌아가는 선택을 제공합니다. 원래 소리 참조가 없는 조명 전용 팩은 이 실패가 아닙니다.
다시 시도는 원본을 바꾸지 않고 팩을 다시 엽니다. 해독·메모리 실패를 호환 성공으로 세지 않습니다.

이 한도는 보관할 소리 값의 양이며 앱 전체 최고 메모리·임시 복사·동시 해독의 보장이 아닙니다.
기존 할당 보호는 유지합니다. 아이폰은 출력 장치와 관계없이 48킬로헤르츠 스테레오로 보관하고
재생 때 장치에 맞춥니다. 기기 메모리·외부 출력·브라우저 차이와 실제 실패는 별도 시험으로
확인하며 모든 브라우저 탭 종료를 막는다고 보장하지 않습니다.
