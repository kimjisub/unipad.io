The `keySound` file maps sound files to each button.
Write one mapping per line, separated by spaces.

## Syntax

```
chain  x  y  soundFile  [loop]  [wormhole]
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `chain` | int | O | Chain number (1 ~ chain) |
| `x` | int | O | Button X coordinate (1 ~ buttonX) |
| `y` | int | O | Button Y coordinate (1 ~ buttonY) |
| `soundFile` | string | O | File path within `sounds/` folder |
| `loop` | int | | Loop setting (see below) |
| `wormhole` | int | | Chain number to switch to, 100 ms after the button is pressed |

### Loop Values

The `loop` value is internally stored with 1 subtracted.

| Written Value | Behavior |
|---------------|----------|
| Omitted or `1` | Play once (default) |
| `0` | Loop indefinitely |
| `N` (2 or more) | Play N times in total |

## Example

```
1 1 1 kick.wav
1 2 1 snare.wav
1 3 1 hihat.wav 0
2 1 1 bass.wav 1 3
```

- `1 3 1 hihat.wav 0` — Chain 1, position (3,1), loop hihat.wav indefinitely
- `2 1 1 bass.wav 1 3` — Chain 2, position (1,1), play bass.wav once and switch to chain 3 100 ms after the press (the sound keeps playing)

## Circular Queue (Multi-mapping)

When multiple sounds are mapped to the same `chain x y` coordinate, they **cycle in order** each time the button is pressed.

```
1 1 1 sound_a.wav
1 1 1 sound_b.wav
1 1 1 sound_c.wav
```

Each press of button (1,1): sound\_a → sound\_b → sound\_c → sound\_a → ...

## Playback

- Releasing the button stops only an endless (`loop` 0) sound it started. A sound that plays once or N times plays to its end.
- Pressing the same button again stops its previous sound and starts the next one, so sounds of one button never overlap. Sounds of different buttons do.
- A `wormhole` that names a chain the pack does not have switches to the nearest chain (chain 1 or the last chain).

## Text Encoding

These rules apply to every text file of a UniPack: `info`, `keySound`, the files in `keyLED` and `autoPlay`.

- UTF-8 is read first; a UTF-8 byte order mark at the start is dropped.
- UTF-16 (little or big endian) that starts with a byte order mark is read.
- A file that is neither is read as CP949 (EUC-KR, the Korean Windows encoding).

Save new files as UTF-8.

<Callout title="Validation">
- Empty lines and lines with fewer than 3 columns are ignored.
- Lines with out-of-range coordinates are skipped with a warning.
- A warning is logged if the referenced sound file is not found in the `sounds/` folder.
- A sound file name whose upper and lower case differ from the file in `sounds/` is still found (a file whose case matches exactly is used first). Write names with the same case as the files anyway.
</Callout>
