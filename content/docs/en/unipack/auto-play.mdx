The `autoPlay` file defines the auto-play sequence.
This data is used in auto-play mode and practice mode.
The text encoding follows the same rules as `keySound`.

## Commands

| Command | Shorthand | Syntax | Description |
|---------|-----------|--------|-------------|
| `on` | `o` | `on x y` | Button press (play sound + start LED) |
| `off` | `f` | `off x y` | Button release |
| `touch` | `t` | `touch x y` | Press + immediate release (on + off in one line) |
| `chain` | `c` | `chain N` | Switch to chain N |
| `delay` | `d` | `delay ms` | Wait in milliseconds |

## Behavior

- Events are executed sequentially from top to bottom.
- The `on` event plays the sound at the given coordinate and advances to the next sound in the circular queue.
- If a sound has a **wormhole** set, executing `on` or `touch` will automatically switch to that chain.
- Whenever the chain changes — by `chain`, a wormhole, a `chain` event in an LED file, or the user — every button of that chain starts its circular queue from the first sound and LED again, even when the new chain is the same as before.

## Example

```
chain 1
on 1 1
on 1 2
delay 100
off 1 1
off 1 2
delay 200
touch 2 1
touch 2 2
delay 100
chain 2
on 1 1
delay 500
off 1 1
```

<Callout title="Notes">
- Consecutive events without `delay` are executed simultaneously.
- Lines with out-of-range coordinates are skipped.
- In practice mode, chain switches automatically pause so the user can practice at their own pace.
</Callout>

## Chain and input ownership

The shared format applies a parsed wormhole immediately, without also scheduling the manual sound's 100 ms chain switch. Stopping auto-play cancels its pending changes. Before each scripted press or release, auto-play restores the chain calculated from its file; a player's chain selection or an LED `chain` event lasts only until that next event.
Manual and auto-play releases end only what their own press currently owns. App updates are aligning these overlapping-input and wormhole rules.

## Completion and editing

The final delay is part of auto-play, including a pause during that wait. Completion releases only auto-play-owned inputs. See [Playback behavior](playback) for interruptions, explicit resume and auto-map with backup and restore.
